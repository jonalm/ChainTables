THE QUESTION (issue #7)
==============================================================================

The builder is the determinism guarantee. Three spellings of the same two
records are in shape_a.jl (plain functions + NamedTuples), shape_b.jl
(do-blocks) and shape_c.jl (a macro DSL). Read those three files side by
side — that is the actual artifact. This output is the evidence that they
are the same thing underneath, and the record of where the guard holds and
where it does not.

Values are always bound parameters, never interpolated, and identifiers
are never quoted — with SQLITE_DQS=3 compiled in (#18) a quoted identifier
that fails to resolve silently becomes a string literal.

5. WHERE THE VALUE GUARD BITES
==============================================================================

  a Bool                                         → DeterminismError: Bool has no SQLite storage class; write 0 or 1 so the record says which (got true)
  a DateTime                                     → DeterminismError: DateTime has no canonical SQLite encoding. Convert it yourself, so the record records the decision (a DateTime → an Int64 epoch or an ISO-8601 String, a Symbol → a String, a Rational → whichever of the two you meant)
  NaN                                            → DeterminismError: REAL must be finite — NaN and Inf have no canonical encoding and no stable text form (got NaN)
  TEXT containing U+0000                         → DeterminismError: TEXT may not contain U+0000 — SQLite truncates the value there and the record would no longer describe the row
  a column named "order"                         → DeterminismError: identifier "order" is an SQL keyword; quoting it is exactly what this builder refuses to do
  a column named "drop table"                    → DeterminismError: identifier "drop table" must match [A-Za-z_][A-Za-z0-9_]* — the builder never quotes identifiers, because with SQLITE_DQS=3 compiled in (#18) a quoted identifier that does not resolve becomes a string literal instead of an error
  a table with no PRIMARY KEY                    → DeterminismError: table x needs an explicit PRIMARY KEY. The implicit rowid is not replayable (#3: max+1 goes random at 2^63-1 and is reused after DELETE), and a materialized UPDATE or DELETE has nothing to name a row by without one
  ADD COLUMN NOT NULL, no default                → DeterminismError: ADD COLUMN site NOT NULL needs a literal DEFAULT — existing rows have to get a value, and it has to be in the record rather than computed at replay time
  rows naming different columns                  → DeterminismError: every row of one INSERT must name the same columns in the same order — column order is part of the canonical bytes (got (:label, :id) after (:id, :label))
  rand() — plain function shape                  → ACCEPTED
  rand() — macro shape                           → LoadError: @record refuses rand(...): its value differs between clients or between runs, so the record would not describe a reproducible write in expression starting at /Users/jonalmeriksen/biome/S3SQLite/prototype/write-builder/run.jl:57
  noise() = rand() — macro shape                 → ACCEPTED
The last three are the finding. Value-level validation cannot see a
non-deterministic *source*, because rand() returns a perfectly canonical
Float64. Only the macro can — and only until someone wraps it in a
function, which is one keystroke away and is also what any real caller
does, since the row sets come from a query in the first place.

6. WHEN THE RECORD DISAGREES WITH LOCAL STATE
==============================================================================

  DELETE of a row not present                    → RecordRejected: transaction 1 ("delete a row that isn't there"), op 1 (delete): RecordRejected: DELETE row 1 matched 0 rows, expected exactly 1 — the caller's materialized row set disagrees with local state, so the record would not replay the same way here
Matching zero rows is an error, not a no-op: the caller materialized a row
set that this database does not have, so the two clients do not agree about
what the record means.
